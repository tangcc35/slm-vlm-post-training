## Overview

Character Card V2 is the open standard for representing AI roleplay personas, behavioral directives, dialogue formatting examples, and narrative context in modular JSON format.

In `story_rp_engine.rp`, Character Card V2 objects provide:
- Strict Pydantic model validation (`CharacterCard`).
- Robust deserialization from JSON strings or Python dictionaries (`load_character_from_json`, `load_character_from_dict`).
- Case-insensitive macro substitution for `{{char}}` and `{{user}}`.
- Structured compilation into roleplay system instructions via `build_rp_system_instruction`.

---

## Data Schema & Field Specifications

The schema is defined in `story_rp_engine.core.types.CharacterCard`:

| Field | Type | Required | Default | Description |
| :--- | :--- | :--- | :--- | :--- |
| `char_id` | `string` | **Yes** | — | Unique identifier used for database persistence, caching, and session routing (e.g. `"kaelen"`, `"elysia"`). |
| `name` | `string` | **Yes** | — | The canonical display name of the persona (e.g. `"Kaelen"`, `"Aria"`). |
| `description` | `string` | No | `""` | Physical appearance, background history, attire, and core character lore. Supports `{{char}}` and `{{user}}` macros. |
| `personality` | `string` | No | `""` | Behavioral traits, quirks, moral compass, tone of voice, and psychological motivations. Supports macros. |
| `scenario` | `string` | No | `""` | The introductory narrative premise, environmental setting, and initial interpersonal dynamics. Supports macros. |
| `first_mes` | `string` | No | `""` | The opening greeting or dialogue turn generated by the character to kick off a new roleplay session. |
| `mes_example` | `string` | No | `""` | Multi-turn dialogue examples demonstrating speech rhythm, vocabulary, and formatting (e.g., `<START>\n{{user}}: ...\n{{char}}: ...`). |
| `system_prompt` | `string \| null` | No | `None` | Optional base system prompt override. When provided, can replace or augment default persona preambles. |
| `post_history_instructions` | `string \| null` | No | `None` | Directives injected at the tail of system instructions or after dialogue history (e.g. formatting constraints, anti-repetition rules). |
| `alternate_greetings` | `list[string]` | No | `[]` | List of alternative opening messages for varied scenarios, scene rerolls, or branching storylines. |
| `creator_notes` | `string \| null` | No | `None` | Author advice, recommended temperature/sampler parameters, or worldbuilding tips (non-injected metadata). |
| `tags` | `list[string]` | No | `[]` | Categorical metadata for search and discovery (e.g., `["fantasy", "ranger", "survival"]`). |

## JSON Validation & Parsing Engine

Character cards are parsed and validated through `story_rp_engine.rp.character`.

### Validation Functions

```python
from story_rp_engine.rp.character import (
    load_character_from_dict,
    load_character_from_json,
)
```

- **`load_character_from_dict(payload: Dict[str, Any]) -> CharacterCard`**:
  Validates dictionary payloads against `CharacterCard.model_validate`. Raises `ValueError("Invalid Character Card: <details>")` if required fields (`char_id`, `name`) are missing or types are invalid.

- **`load_character_from_json(json_str: str) -> CharacterCard`**:
  Deserializes JSON strings. Handles parsing edge cases:
  - If `json_str` is invalid JSON: raises `ValueError("Malformed JSON: ...")`.
  - If `json_str` is not a JSON object (e.g. array, integer, string literal): raises `ValueError("Invalid Character Card: expected JSON object")`.
  - Delegates dictionary validation to `load_character_from_dict`.

### Error Handling Examples

```python
# 1. Missing required field 'name'
try:
    load_character_from_dict({"char_id": "ranger", "description": "A silent tracker"})
except ValueError as e:
    # Raises: "Invalid Character Card: 1 validation error for CharacterCard\nname\n  Field required"
    pass

# 2. Malformed JSON string
try:
    load_character_from_json("{invalid_json: true,}")
except ValueError as e:
    # Raises: "Malformed JSON: Expecting property name enclosed in double quotes..."
    pass

# 3. Non-dictionary JSON root
try:
    load_character_from_json('"just a string"')
except ValueError as e:
    # Raises: "Invalid Character Card: expected JSON object"
    pass
```

## Macro Substitution Mechanics

Dynamic prompts allow character cards to remain reusable across different user handles and persona references.

### Supported Macros

| Macro Placeholder | Replaced With | Case Handling |
| :--- | :--- | :--- |
| `{{char}}` | `card.name` | Case-insensitive (`{{char}}`, `{{Char}}`, `{{CHAR}}`) |
| `{{user}}` | User's configured name (`user_name`, defaults to `"User"`) | Case-insensitive (`{{user}}`, `{{User}}`, `{{USER}}`) |

### Substitution Engine (`story_rp_engine.rp.prompt_builder.replace_macros`)

```python
def replace_macros(text: Optional[str], char_name: str, user_name: str) -> str:
    if not text:
        return ""
    text = re.sub(r"\{\{char\}\}", char_name, text, flags=re.IGNORECASE)
    text = re.sub(r"\{\{user\}\}", user_name, text, flags=re.IGNORECASE)
    return text
```

### Safety & Edge Case Guarantees
- **Null Safety**: `replace_macros(None, ...)` and `replace_macros("", ...)` return `""` cleanly without raising `AttributeError`.
- **Case Variations**: `{{Char}} greeted {{USER}}. {{CHAR}} nodded to {{User}}.` correctly converts to `{char_name} greeted {user_name}. {char_name} nodded to {user_name}.`
- **Fields Processed**: `replace_macros` is automatically applied to `description`, `personality`, `scenario`, `mes_example`, and `post_history_instructions` during system instruction construction.

## System Instruction Assembly Layout

The function `build_rp_system_instruction` in `story_rp_engine.rp.prompt_builder` compiles the character card, active lore entries, and user configuration into a coherent system prompt.

### Prompt Section Hierarchy

1. **Roleplay Foundation Preamble**:
   ```text
   You are roleplaying as {char_name}. Stay fully in character at all times. Do not break the fourth wall or speak for {user_name}.
   ```
2. **Character Specification**:
   ```text
   ### Character: {char_name}
   - Description: {processed description}
   - Personality: {processed personality}
   ```
3. **Scenario Context**:
   ```text
   ### Scenario
   {processed scenario}
   ```
4. **World Information & Lore** *(appended only if `active_lore` is non-empty)*:
   ```text
   ### World Information & Lore
   - {lore entry 1 content}
   - {lore entry 2 content}
   ```
5. **Dialogue Examples** *(appended only if `mes_example` is present)*:
   ```text
   ### Dialogue Examples
   {processed mes_example}
   ```
6. **Additional Directives** *(appended only if `post_history_instructions` is present)*:
   ```text
   ### Additional Directives
   {processed post_history_instructions}
   ```

All populated sections are joined using double newlines (`"\n\n"`).

## Python Programmatic Usage

### Loading and Inspecting a Character Card

```python
import json
from story_rp_engine.rp.character import load_character_from_json
from story_rp_engine.rp.prompt_builder import build_rp_system_instruction

# 1. Load card from JSON
with open("data/characters/kaelen.json", "r", encoding="utf-8") as f:
    card = load_character_from_json(f.read())

print(f"Loaded character: {card.name} (ID: {card.char_id})")
print(f"Tags: {card.tags}")

# 2. Render system instruction for a specific user
system_instruction = build_rp_system_instruction(
    card=card,
    active_lore=None,
    user_name="Seraphina",
)
print(system_instruction)
```

### In-Memory Card Construction

```python
from story_rp_engine.core.types import CharacterCard

card = CharacterCard(
    char_id="elora_mage",
    name="Elora",
    description="{{char}} is an archivist of the Grand Arcanum.",
    personality="Analytical, soft-spoken, intrigued by forgotten runes.",
    scenario="{{user}} arrives at the restricted archives seeking forbidden texts.",
    first_mes="The ink on these scrolls has remained undisturbed for three centuries. What brings you to this quiet corner, {{user}}?",
)
```
